## 1. 背景与目标

李黎需要在实习面试前反复练习十个实习案件，目标不是刷机考题，而是能够准确、完整地讲清案件事实、证据、本人工作、法律争点、裁判理由、结果和复盘。

主要使用人：李黎。内容可由朋友或教材制作人协助维护。最初面向 Mac 本地浏览器，随后为方便分发和内容更新，增加手机浏览器与临时在线访问。

系统评分和准备度只是自设学习反馈，不是官方面试合格结论，也不预测考官真题。

## 3. 已确认的需求与决策

### 3.1 学习内容

- 使用核心卡、进阶卡和串联卡，不以碎卡代替完整案件表达。
- 每案包含案件地图、证据与本人工作、法律争点、复盘与关联案件、面试表达与压力追问。
- 每张卡必须有稳定 ID 和材料来源；不得编造事实、案号、法条、结果或本人角色。
- 教材制作过程中的原始材料位于本地 `.tmp/`，已通过 `.gitignore` 排除，不上传 GitHub。
- 内容升级沿用稳定卡片 ID，不因 `contentVersion` 变化主动重置旧进度。

### 3.2 学习与评分

- 普通卡可在显示答案前直接自评，查看答案为可选操作；串联陈述仍需显示核对点。
- 三档自评：不会（again）、模糊（fuzzy）、会（good）。
- again 约三张后重现，fuzzy 约十张后重现；同一 session 自动重现最多两次。
- good 按连续次数进入下一 session、次日 07:00 或稳定状态。
- 支持完整撤销最近一次评分，恢复卡片、队列、进度和原始记录。
- 支持逐案学习、混合复习、错卡急救、章节检查和串联表达。
- 串联卡使用计时与人工核对点，不用短答案匹配代替口头表达评价。
- 章节失败后指出具体薄弱卡，不强制整章重学。

### 3.3 手机操作

- 普通卡可直接点击不会、模糊、会，无需先显示答案；串联陈述全部核对后才能通过。
- 按用户后续确认，卡片题面／空白处左滑不会、右滑会、下滑模糊，正常松手后才评分；长答案在独立区域内滚动。
- 三向手势跟手位移并显示红／绿／黄方向提示，达到 60px 提示松手标记；小位移／取消回弹，成功后显示确认提示和下一张入场。
- 答案区内的手势和键盘方向键用于滚动，不评分；减少动态效果时保留颜色与文字提示。
- 小距离、斜滑、多指、取消和从控件开始的手势不评分；一次手势只评分一次。
- 手机评分区在卡片下方独立排列，长答案在卡片内滚动；不足 500px 高的短屏改为整页自然滚动，避免裁切。
- 键盘左右直接评分；空格或首次下键显示答案，答案显示后下键评为模糊。

### 3.4 登录与数据保留

- 访问密码只需首次输入；验证状态保存在 `localStorage`，刷新或之后重开同一网址不重复登录。
- 学习记录不是只保存一天，而是持续保存在当前浏览器。
- 学习数据 key：`lili-interview-trainer:v1`；访问状态使用独立 key，互不覆盖。
- 同一设备、同一浏览器、同一网址下，功能修复和内容部署不会主动清空学习数据。
- 正在学习的页面不会被远程强制刷新；下次自然刷新后使用新版并恢复当前队列。
- 清除网站数据、无痕模式、换浏览器、换设备或换域名会导致原记录不可见。
- 提供 JSON 导出和确认后导入替换，建议每天学习后导出备份。
- 损坏数据不会被静默覆盖，提供人工恢复路径。

### 3.5 在线发布与安全边界

- 用户为方便使用和内容更新，明确选择将当前正式内容发布到自己的 GitHub Pages。
- 链接不主动公开转发，并增加随机密码门禁作为短期防误闯措施。
- 不使用最初提议的六位简单密码 `131211`。
- 必须持续明确：GitHub Pages 是公开静态托管，前端密码不能阻止有技术能力的人下载或提取打包内容，不能替代服务端鉴权。
- 不向外部服务上传学习记录，不添加分析埋点或第三方追踪。
- 若未来需要真正私密访问，应迁移到具备服务端访问控制的部署方式。

## 4. 功能范围

已实现：十案课程、内容校验、三档评分、间隔调度、错卡重现、撤销、本地恢复、课程与章节导航、混合与错卡模式、成长记录、准备度核对、串联计时、JSON 备份、响应式手机界面、一次登录、触摸手势和 GitHub Pages 自动更新。

仍不包含：账号体系、云同步、后端、多人协作、AI 自动出题或口头答案判定、原生 Mac App／DMG、机考／政治题模块、录音回听。

## 5. 技术与文件地图

- React 19 + TypeScript + Vite + Zod。
- Vitest + Testing Library；领域规则写成不依赖 UI 的纯函数。
- `src/App.tsx`：首页、课程、学习、成长记录和交互。
- `src/AccessGate.tsx`：访问密码与持久登录状态。
- `src/domain/scheduler.ts`：队列、评分、调度与 session。
- `src/domain/progress.ts`：队列筛选、错卡、章节表现和准备度。
- `src/domain/persistence.ts`：本地校验、版本拒绝、导入导出。
- `src/domain/content.ts`：十案五章与卡片契约校验。
- `src/content/index.ts`：正式课程聚合。
- `content/courses/`：十门正式课程 JSON。
- `content/manifest.json`：内容版本、状态和顺序。
- `src/styles.css`：桌面、移动、固定评分栏、焦点和减少动态效果。
- `docs/SPEC.md`、`docs/CONTENT_SPEC.md`、`docs/TDD_PLAN.md`：原始产品与内容规格；本文档记录后续已确认决策。

## 7. 后续更新流程

1. 修改课程 JSON 或功能代码；内容更新保持既有卡片 ID 不变。
2. 按 TDD 为可观察行为先写失败测试，再写最小实现。
3. 本地运行 `npm test`、`npm run typecheck`、`npm run build`。
4. 按用户 2026-11-04 授权，检查范围、敏感信息和远端分歧后直接提交并推送到 `main`，不再逐次请求发布确认。
5. 等待 GitHub Actions 成功，再访问同一 Pages 地址验收。
6. 不更换网址，不修改本地存储 key；若确需 schema 迁移，必须先写迁移测试并保留旧记录。
7. 提醒李黎定期导出 JSON，尤其是浏览器清理或换设备之前。
