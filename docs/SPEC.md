# 产品规格：李黎面试训练器

版本：0.1（开发基线）  
目标平台：Mac 本地浏览器应用  
开发方式：TDD

## 1. 产品目标

帮助李黎在实习面试前完成三类训练：

1. 准确回忆十个实习案件的事实、证据、结果和本人工作；
2. 理解法律争点、裁判理由、复盘和关联案件差异；
3. 从原子知识过渡到 20 秒结论、90 秒案件陈述和连续压力追问。

系统围绕面考表达与材料理解，不是普通背词工具，也不预测考官原题。

## 2. 用户与使用环境

- 唯一用户：李黎；朋友可协助维护内容。
- 设备：Mac，本地浏览器，键盘操作为主，兼顾触摸按钮。
- 数据：仅本机保存，可导出 JSON 备份；无账号、无云同步。
- 使用场景：短时间多次学习、错卡重刷、章节检查、案件串联和考前混合复习。

## 3. 明确范围

### 第一版包含

- 十门案件课程及五类固定章节；
- 核心卡、进阶卡、串联卡；
- 问答、填空、证据目的、比较、纠错、追问和案件陈述等题型；
- 显示答案、三档自评、撤销误触；
- 间隔重复、错卡重现、本地学习记录；
- 课程／章节掌握度、学习轨迹、面试准备度；
- 逐案、混合、错卡三种训练模式；
- JSON 导出与导入；
- Mac 本地运行与离线使用。

### 第一版不包含

- 机考／笔试题库、政治题刷题模块；
- 原生 Mac App、DMG、签名或安装器；
- 公网部署、账号、后端和多人协作；
- AI 自动出题或自动判定口头答案；
- 将系统掌握度解释为官方合格概率；
- 录音回听（可作为后续版本，不影响第一版交付）。

## 4. 信息架构

采用四级结构：

```text
案件课程 Course
  └── 能力章节 Chapter
        └── 学习卡 Card
              └── 章节检查／案件串联 Assessment
```

碎卡是记忆单元，案件是学习主线。任何卡片页面都显示“课程 › 章节 › 卡片类型”，并提供返回案件地图的路径。

### 4.1 十门课程

| courseId | 课程 |
|---|---|
| labor-arbitration | 劳动争议仲裁 |
| return-property | 返还原物纠纷 |
| obtaining-loan-by-fraud | 骗取贷款刑事案 |
| cross-border-family | 跨境家事项目 |
| post-divorce-property | 离婚后财产纠纷 |
| digital-assets | 公司数字资产纠纷 |
| trademark-transfer | 商标转移纠纷 |
| equity-design | 股权设计非诉项目 |
| elder-care-fall | 养老机构摔伤案 |
| elder-care-choking | 养老机构窒息死亡案 |

### 4.2 每门课程的五个章节

| chapterId | 章节 | 必须回答的问题 |
|---|---|---|
| case-map | 案件地图 | 谁、发生什么、诉求、程序阶段、结果 |
| evidence-contribution | 证据与本人工作 | 证据证明什么、李黎具体做了什么、团队边界 |
| legal-issues | 法律争点 | 要件、双方观点、裁判理由、法律区别 |
| review-comparison | 复盘与关联案件 | 如何改进、与他案有何异同 |
| interview-performance | 面试表达与压力追问 | 20 秒结论、90 秒陈述、连续追问、纠错止损 |

不强制线性解锁；时间紧时可直接进入高风险章节或错卡模式。

## 5. 内容分层与题型

### 5.1 三层内容

- **核心卡**：案件事实、结果、关键证据、本人工作、核心规则。默认优先学习。
- **进阶卡**：反方观点、证明限制、策略比较、关联案件、压力追问。可按时间开启。
- **串联卡**：完整口头表达，不再提供一句短答案，而提供评分核对点。

丰富内容不等于一次全部展示。默认学习路径为核心卡→章节检查→串联卡→进阶／混合。

### 5.2 题型

| 类型 | 用途 | 示例形式 |
|---|---|---|
| qa | 单项事实或规则回忆 | “仲裁结果是什么？” |
| cloze | 易混数字、日期、术语 | “员工请求金额为____元” |
| evidence-purpose | 证据与证明目的连接 | “人员职责对照表用于证明什么？” |
| comparison | 区分相似案件或概念 | “同为 20%，两起养老案理由是否相同？” |
| correction | 识别越界或错误表述 | “‘登记后即可执行’错在哪里？” |
| follow-up | 连续追问 | 结论后追加一个反方问题 |
| summary | 20 秒／90 秒口头输出 | 提供计时器和评分核对点 |

### 5.3 长度约束

- 原子卡题面目标不超过 60 个汉字；答案目标不超过 100 个汉字或 3 个短要点。
- 超过此长度优先拆分，但不得切断必要的因果或法律层次。
- 串联卡不受短答案限制，只显示任务、时限和 3—6 个评分核对点。
- 卡片必须保留课程与章节上下文，避免“记得碎片、讲不出案件”。

## 6. 核心刷题交互

### 6.1 未显示答案

- 页面只显示课程路径、题面、进度和“显示答案”提示。
- `Space` 或 `ArrowDown`：显示答案。
- `ArrowLeft`、`ArrowRight`：不生效，不得误评。
- 手机／触摸端显示“显示答案”大按钮。

### 6.2 已显示答案

- `ArrowLeft`：不会（again）。
- `ArrowDown`：模糊（fuzzy）。
- `ArrowRight`：会（good）。
- 触摸端显示同义三档大按钮。
- 提示：“3 秒内能完整说出，才按‘会’。”

### 6.3 其他操作

- `Cmd/Ctrl+Z`：撤销最近一次评分，恢复评分前卡片和调度快照。
- 切换课程、离开页面或刷新不得丢失已评分记录。
- 防止一次长按或重复 keydown 造成多次评分。
- 串联卡提供开始／暂停／重置计时，不强制自动评分。

## 7. 训练模式

### 逐案学习

按课程与章节组织，核心卡优先。每章结束提供换问法检查，不仅重复原句。

### 混合复习

跨课程交错出现，优先到期卡、错卡和高风险卡。用于训练快速切换及防止案件混淆。

### 错卡急救

只包含 again、fuzzy、曾答错或串联检查未通过的卡。清零不是删除历史，而是最近规定次数内稳定答对。

## 8. 间隔重复规格

这是面向临近面试的压缩间隔，不声称精确复现某种科学曲线。实现必须写成可测试纯函数。

### 8.1 自评与调度

| 自评 | 结果 |
|---|---|
| again | 当前队列约 3 张卡后重现；本轮结束前再次出现；稳定等级降级 |
| fuzzy | 当前队列约 10 张卡后重现；记录为模糊 |
| good（首次） | 下一学习 session 再到期 |
| good（连续第二次） | 次日早晨到期，默认本地 07:00 |
| good（连续第三次） | 标记 stable；面试前不默认高频出现，可在高风险／错卡模式主动复习 |

- 同一卡在当前队列中不得重复占位。
- 同一 session 内自动重现最多 2 次，之后进入下一 session，避免死循环。
- 新卡默认按核心优先；进阶卡是否进入由用户选择。
- again／fuzzy 后再次 good，连续 good 次数按产品规则重新累计。
- 所有时间比较使用可注入时钟，测试不得依赖真实等待。

### 8.2 撤销

评分时保存不可变快照。撤销需要恢复卡片队列位置、进度、掌握度、连续答对次数、到期时间和学习记录；不得只改页面而不改数据。

## 9. 学习记录与成长记录

### 9.1 原始记录

每次评分至少保存：

- attemptId、sessionId、cardId、courseId、chapterId；
- mode、rating、revealedAt、ratedAt、responseMs；
- rating 前后的复习状态；
- 串联卡的人工完成结果与用时（如适用）。

不得只存一个总分而丢失可解释依据。

### 9.2 首页信息

1. 今日待复习、学习中、稳定、未学习数量；
2. 十门课程的完成度和最近学习状态；
3. 五项章节能力的表现；
4. 最近学习 session 与错卡变化；
5. 高风险错卡和未通过串联卡。

### 9.3 有意义的成长事件

例如“返还原物案连续两次通过章节检查”“两起养老案比较卡由模糊变为稳定”。不得仅用学习分钟数或刷卡数量制造进步感。

### 9.4 面试准备度（自设学习反馈）

建议同时满足：

- 核心卡全部学习；
- 五个章节均完成检查；
- 每案至少一次串联陈述；
- 没有未纠正的红线卡；
- 高风险错卡最近两次稳定答对。

准备度不是官方合格预测。没有足够记录时显示“未评估”，不能虚构百分比。

## 10. 本地持久化与备份

- 使用带版本号的本地存储，建议 key：`lili-interview-trainer:v1`。
- 启动时校验数据结构；损坏数据应提示并保留恢复选择，不静默覆盖。
- 导出 JSON 包含 schemaVersion、exportedAt、内容版本、卡片进度、attempts 和 sessions。
- 导入前校验并让用户确认替换或合并；第一版可只实现“确认后替换”。
- 不提供第三方分析、追踪或自动上传。

## 11. 内容与事实安全

- 事实只能来自已核验实习材料或用户明确确认的内容。
- 未结案件不得写成胜诉；团队工作不得写成李黎独立主办。
- 内容包含 sourceRefs，便于回查；无来源内容不得进入正式核心题库。
- 不确定法条、案号或上次面试反馈不得由系统补写。
- 课程学习目标是准备可能考察范围，不宣称考官会问某题。

## 12. 可用性与无障碍

- Mac 常见浏览器中布局不溢出，核心操作可全键盘完成。
- 按钮有可见文字，不只依赖颜色和图标。
- 焦点状态清晰；答案出现后不强制跳到页面顶部。
- 支持减少动态效果；不使用依赖动画的学习反馈。
- 触摸目标足够大，避免三档评分过近造成误触。

## 13. 性能与离线

- 首版内容本地打包，无运行时网络依赖。
- 数百张卡及学习记录下，常规操作应即时响应。
- 刷新后恢复最近课程、模式与调度状态。
- 生产构建成功，控制台无未处理错误。

## 14. 第一版完成标准

- `docs/TDD_PLAN.md` 的 P0 场景全部有自动化测试并通过；
- 十门课程可导入并通过内容校验；
- 完整跑通“选课程→学习→评分→错卡重现→章节检查→串联卡→导出记录”；
- 键盘与触摸路径均验证；
- 测试、类型检查和生产构建通过；
- 页面明确区分学习反馈与官方考核结论。
