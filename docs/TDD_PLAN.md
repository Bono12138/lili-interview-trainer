# TDD 实施计划与验收场景

## 1. 工作方式

严格按 Red → Green → Refactor：

1. 从本文件选取一个可观察行为，先写失败测试；
2. 运行并确认失败原因正确；
3. 写最小实现使其通过；
4. 保持绿色重构；
5. 完成纵向切片后运行完整测试、类型检查和构建。

不要一次性生成整个应用再补测试，不要为了通过而删除断言或降低规格。

## 2. 测试分层

### A. 纯领域单元测试

覆盖调度、队列、掌握度、准备度、内容校验、记录迁移。使用表驱动测试、固定 ID 和可注入时钟。

### B. React 集成测试

使用 Testing Library，验证真实用户路径：显示答案、键盘评分、按钮评分、撤销、课程切换、计时和恢复。

### C. 内容测试

直接加载正式课程 JSON，检查十案、五章、唯一 ID、答案结构和来源引用。不得只用假数据证明正式内容有效。

### D. 关键浏览器验收（实现后）

验证生产构建中的完整流程、离线运行、刷新恢复和 Mac 键盘操作。浏览器环境可用后补充，不得以手测替代已有单元／集成测试。

## 3. 推荐实施顺序

每个切片均先写测试：

1. 内容 schema 与课程清单校验；
2. 单卡显示答案及三档评分；
3. 队列调度与错卡重现；
4. 本地进度保存、刷新恢复和撤销；
5. 课程／章节导航及章节检查；
6. 混合与错卡模式；
7. 成长记录与准备度；
8. 串联卡计时和人工核对；
9. JSON 导出／导入；
10. 完整内容导入、响应式和离线验收。

## 4. P0 领域测试清单

### 调度器

- again 在当前队列约 3 张后重现，并降级稳定状态；
- fuzzy 在当前队列约 10 张后重现；
- good 的连续次数和到期时间符合 SPEC；
- 同一卡不在队列中重复占位；
- 同 session 自动重现不超过 2 次；
- 空队列、单卡、全部到期、无到期等情况不死循环；
- 新内容加入不会破坏既有进度；
- 时区和“次日 07:00”由可注入时钟确定。

### 掌握度与准备度

- 点击次数不等于稳定掌握；
- 换题型答对才产生额外章节检查进度；
- 稳定卡答错会降级；
- 红线卡未纠正时准备度不得通过；
- 缺少记录时显示未评估而非虚构百分比；
- 准备度结果不被描述成官方合格预测。

### 内容校验

- 重复 ID、无效章节、缺失答案、缺失来源均失败；
- summary 缺少 checklist 失败；
- 十案五章缺失能给出具体错误路径；
- 有效正式内容通过；
- 内容版本升级保留稳定卡片 ID 的历史。

### 持久化

- 保存后可完整恢复；
- JSON 导出再导入保持进度等价；
- 损坏数据不静默覆盖，并显示恢复选择；
- 不支持的未来 schemaVersion 被明确拒绝；
- 导入替换需要用户确认。

## 5. P0 交互验收场景

### 场景 1：显示答案

```text
Given 一张未显示答案的卡片
When 用户按 Space 或 ArrowDown
Then 显示对应答案和三档评分
And 不自动记录任何自评
```

### 场景 2：防止误评

```text
Given 答案尚未显示
When 用户按 ArrowLeft 或 ArrowRight
Then 卡片状态和进度均不改变
```

### 场景 3：不会后重现

```text
Given 答案已显示
When 用户按 ArrowLeft
Then 记录 again
And 该卡按规则重新进入当前队列
And 页面进入下一张不同卡片
```

### 场景 4：模糊与会

```text
Given 答案已显示
When 用户按 ArrowDown 或 ArrowRight
Then 分别记录 fuzzy 或 good
And 调度结果与 SPEC 一致
And 未显示答案时 ArrowDown 仍只承担显示答案功能
```

### 场景 5：撤销

```text
Given 用户刚完成一次评分
When 用户按 Cmd/Ctrl+Z
Then 恢复评分前卡片、队列、进度和记录
And 后续调度与未发生该评分一致
```

### 场景 6：触摸等价

```text
Given 使用触摸界面
When 用户依次点击显示答案和任一自评按钮
Then 与对应键盘路径产生相同领域结果
```

### 场景 7：刷新恢复

```text
Given 用户已有学习记录
When 刷新页面或重新打开本地应用
Then 恢复课程、队列和学习记录
And 不生成重复 attempt
```

### 场景 8：章节检查

```text
Given 用户完成一个章节的核心学习
When 进入章节检查
Then 系统使用换问法或不同题型
And 失败时指向具体薄弱卡片而非强制整章重学
```

### 场景 9：串联卡

```text
Given 一张 90 秒串联卡
When 用户开始计时并完成自评
Then 记录用时和核对结果
And 不用短答案匹配替代口头表达评估
```

### 场景 10：错卡急救

```text
Given 存在 again、fuzzy 和 stable 卡
When 进入错卡急救
Then 只展示符合错卡规则的内容
And 稳定卡不会仅因历史较老被误判为错卡
```

### 场景 11：导出导入

```text
Given 用户有跨多个课程的学习记录
When 导出后清除环境并重新导入
Then 卡片进度、attempts 和 sessions 等价恢复
And 文件包含 schemaVersion 与 contentVersion
```

### 场景 12：离线隐私

```text
Given 应用已完成本地加载
When 网络不可用
Then 核心学习、记录和导出仍可使用
And 不向外部服务发送案件内容或学习记录
```

## 6. 覆盖率与质量门槛

- 调度、内容校验、持久化迁移：目标分支覆盖率 100%；
- 整体语句／分支覆盖率：目标不低于 80%；
- 键盘和触摸等价路径必须有集成测试；
- `npm test`、`npm run typecheck`、`npm run build` 全部通过；
- 不使用无意义快照充覆盖率，不以 console 输出代替断言。

## 7. 当前骨架测试

`src/App.test.tsx` 只验证工具链能渲染占位页，不代表任何业务功能已完成。开始第一个业务切片时，应先新增对应失败测试。
